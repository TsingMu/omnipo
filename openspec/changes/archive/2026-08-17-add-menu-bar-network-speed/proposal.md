# Proposal：add-menu-bar-network-speed

## 背景

Omnipo 已通过 `NSStatusItem` 提供菜单栏入口，并允许用户在设置中控制“显示菜单栏图标”。应用也已经使用公开的 BSD `getifaddrs()` 接口实现整机网络累计字节采样，但该数据目前只在“系统监控”页面活跃时展示。用户希望不打开主窗口即可持续看到当前上传和下载速率，并要求上传、下载在菜单栏图标右侧上下排列。

## 问题

- 当前菜单栏仅显示 Omnipo 图标，不能直接反映网络活动。
- 复用页面级 `SystemMonitorService` 会连带执行 CPU、内存、能耗和磁盘采样，并与“进入页面启动、离开页面停止”的既有生命周期冲突。
- `NSStatusBarButton` 的普通单行标题不适合稳定展示上下两行速率；直接插入换行可能被裁切，并可能破坏菜单点击区域。
- 实时展示需要明确采样频率、隐藏/退出时的停止语义、睡眠唤醒处理和日志隐私边界。

## 目标

- 在菜单栏图标右侧增加两行实时网络速率：上传在上，下载在下。
- 保留现有菜单内容和整块状态项的点击行为。
- 复用 `NetworkSampler` 的公开 API 采样逻辑，但使用独立、轻量的菜单栏采样生命周期，不启动完整系统监控服务。
- 菜单栏状态项可见时按 1 秒间隔采样；隐藏状态项或应用退出时停止采样并释放任务。
- 使用紧凑、等宽数字格式，降低数值变化引起的视觉抖动。
- 在采样预热或暂时不可用时显示明确占位，不伪造实时速率。
- 保持所有流量数据仅在内存中，不记录具体速率或网络接口名，不申请额外系统权限。

## 非目标

- 不展示单个应用、进程或连接的网络用量。
- 不读取域名、IP 地址、端口、数据包内容或用户网络内容。
- 不保存历史曲线、累计用量或每日/月度统计。
- 不提供悬浮窗口、阈值告警、通知或速率颜色主题。
- 不在本 change 中增加独立的“显示网速”开关；现有“显示菜单栏图标”开关控制整个图标与网速组合状态项。
- 不改变主窗口“系统监控”页面的采样间隔和页面生命周期。

## 受影响能力

- `application-foundation`：增强应用级菜单栏状态项、可见性设置响应和后台活动生命周期。
- `system-monitor`：只复用既有 `NetworkSampler` 和网络速率模型，不修改已合并的页面级需求。

## 成功标准

- 启用“显示菜单栏图标”后，菜单栏显示 Omnipo 图标，右侧上行展示上传速率、下行展示下载速率。
- 速率以 `B/s`、`K/s`、`M/s`、`G/s` 的紧凑形式展示，数字使用等宽样式，状态项宽度在正常变化时保持稳定。
- 首次采样完成差值计算前显示 `--`；第二次及后续采样显示真实非负速率。
- 点击图标或两行速率的任意区域均打开现有菜单，菜单项行为不变。
- 关闭菜单栏图标后 1 秒采样任务停止；再次开启后重新预热，不使用隐藏期间的旧计数计算突发速率。
- `getifaddrs()` 失败时界面安全降级为 `--`，其他菜单能力继续可用。
- Debug 构建、相关单元测试及人工验收通过；日志中不出现速率数值或接口名。
