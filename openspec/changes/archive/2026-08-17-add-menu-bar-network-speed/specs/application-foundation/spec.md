# application-foundation 增量规范：菜单栏双行实时网速

## ADDED Requirements

### Requirement: 菜单栏状态项必须展示双行实时网络速率

当菜单栏状态项可见时，系统 MUST 在 Omnipo 图标右侧展示整机实时上传和下载速率。上传 MUST 位于上行，下载 MUST 位于下行，并使用方向符号或等价的可理解标识区分。系统 MUST 使用稳定、紧凑且可读的格式，数值变化不得持续改变状态项宽度或造成明显布局抖动。

#### Scenario: 完成网络采样预热

- **当** 菜单栏状态项可见并已取得至少两次有效网络计数样本
- **那么** 图标右侧上行显示当前上传速率
- **并且** 图标右侧下行显示当前下载速率
- **并且** 上传和下载不得颠倒

#### Scenario: 网络处于空闲状态

- **当** 两次采样之间没有可测量的上传或下载字节增量
- **那么** 对应方向显示非负的零速率
- **并且** 系统不得显示负数或沿用旧的非零速率

#### Scenario: 速率跨越显示单位

- **当** 网络速率从字节级变化到千、兆或吉字节级
- **那么** 系统使用紧凑的 `B/s`、`K/s`、`M/s` 或 `G/s` 格式
- **并且** 使用等宽数字或等价布局约束保持文本位置稳定

### Requirement: 菜单栏网络速率必须正确处理预热与不可用状态

系统 MUST 使用两次累计字节计数的差值计算实时速率。首次样本尚不能计算差值时 MUST 显示预热占位；底层公开 API 暂时不可用时 MUST 显示不可用占位。系统 MUST NOT 以伪造的零速率代替预热或读取失败。

#### Scenario: 首次显示状态项

- **当** 状态项刚显示且仅取得第一次累计字节计数
- **那么** 上传和下载两行均显示 `--` 或等价预热占位
- **并且** 不把首次样本展示为真实零速率

#### Scenario: 网络接口计数读取失败

- **当** `getifaddrs()` 或对应计数读取失败
- **那么** 上传和下载两行显示不可用占位
- **并且** 菜单栏图标及原有菜单仍可使用
- **并且** 不弹出阻塞式错误窗口

### Requirement: 菜单栏网络采样必须遵守可见性生命周期

系统 MUST 仅在菜单栏状态项可见期间执行实时网络采样。状态项隐藏或应用退出时 MUST 取消采样任务并清空本次差值基线；再次显示时 MUST 建立新基线并重新预热。系统 MUST NOT 为菜单栏网速启动包含 CPU、内存、能耗或磁盘读取的完整系统监控服务。

#### Scenario: 用户隐藏菜单栏图标

- **当** 用户关闭“显示菜单栏图标”设置
- **那么** 系统停止菜单栏网络采样并隐藏整个组合状态项
- **并且** 不保留继续运行的 1 秒采样任务

#### Scenario: 用户再次显示菜单栏图标

- **当** 用户重新打开“显示菜单栏图标”设置
- **那么** 系统显示图标和双行速率区域
- **并且** 清空隐藏前的差值基线
- **并且** 首次样本显示预热占位，随后恢复真实速率

#### Scenario: 系统监控页面同时活跃

- **当** 菜单栏网速与主窗口系统监控页面同时显示
- **那么** 两者使用各自受控的采样生命周期
- **并且** 菜单栏不得启动磁盘或其他无关维度采样
- **并且** 任一方停止不得终止另一方仍需运行的网络采样

### Requirement: 双行展示不得破坏状态项菜单交互

系统 MUST 保留既有 `NSStatusItem` 菜单入口。图标、上传行和下载行的全部可见区域 MUST 属于同一个可点击状态项；自定义展示内容不得截获事件并形成无响应区域。现有打开主窗口、打开 Launcher、导航、设置和退出菜单项 MUST 保持原有行为。

#### Scenario: 点击状态项任意区域

- **当** 用户点击图标、上传速率或下载速率区域
- **那么** 系统打开同一个现有菜单
- **并且** 不要求用户精确点击图标

#### Scenario: 速率每秒更新

- **当** 菜单已经打开且后台产生新的速率样本
- **那么** 菜单项结构和当前键盘焦点保持稳定
- **并且** 速率刷新不得触发菜单重建或关闭菜单

### Requirement: 菜单栏网络速率必须保护隐私并支持辅助功能

系统 MUST 仅读取整机网络接口累计入站和出站字节数，不得读取网络内容或连接目标。速率、接口名和采样时间戳 MUST 仅保存在短暂内存状态中，不得持久化、上传或写入日志。状态项 MUST 为 VoiceOver 提供明确区分上传和下载的可访问描述，但 MUST NOT 每秒主动播报速率变化并打断用户。

#### Scenario: 审计采样数据边界

- **当** 菜单栏网速持续运行
- **那么** 系统只读取累计字节计数
- **并且** 不读取 IP 地址、端口、域名、数据包内容或应用归属
- **并且** 不申请额外系统权限
- **并且** 不向磁盘、日志或网络写入具体速率与接口名

#### Scenario: 使用 VoiceOver 聚焦状态项

- **当** VoiceOver 用户将焦点移到菜单栏状态项
- **那么** 系统提供包含 Omnipo、上传速率和下载速率的可理解描述
- **并且** 方向差异不只依赖图标或视觉位置
- **并且** 后续每秒更新不会主动抢占语音输出
