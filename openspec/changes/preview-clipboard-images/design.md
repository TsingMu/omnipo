# Design: 剪贴板图片缩略图

## Context

`ClipboardContentReader` 已将图片识别为 `.image`，`DefaultClipboardService` 会把原始图片数据写入 `BinaryContentStore`，并通过 `ClipboardRepository` 保存对应的 `.image` payload 元数据。列表查询只返回 `ClipboardItem`；图片记录没有 `textPreview`，因此当前两套行视图只能显示通用图片符号和“图片”文字。

主 Clipboard 页面与浮动面板共享 `ClipboardService`，但分别拥有行视图。缩略图读取必须保留现有服务边界，不让 UI 直接访问数据库或 payload 文件路径。

## Decisions

### 1. 通过 Clipboard 服务读取有界缩略图

扩展 `ClipboardService`，提供按记录 ID 异步请求图片缩略图的能力。默认实现仅为 `.image` 记录查询 `.image` payload，并通过 `BinaryContentStore` 读取数据。

服务使用 ImageIO 的缩略图能力按最大像素尺寸降采样，不在主线程构造或解码完整尺寸位图。返回值使用可跨并发域传递的有界数据表示；UI 再将其转换为 `NSImage` 展示。

不可用 Clipboard 服务对该操作返回与其他 Clipboard 操作一致的 capability 不可用错误。

### 2. 使用内存中的有界缓存

同一图片可能同时出现在主页面和浮动面板，并在 SwiftUI 行重建时重复请求。默认服务按记录 ID 与目标像素尺寸缓存成功生成的缩略图，缓存只存在于当前进程，不写入磁盘。

缓存必须设置总成本上限；删除记录后即使缓存尚未淘汰，也不得使已删除记录重新出现在列表中。失败结果不长期缓存，以允许临时读取问题恢复。

### 3. 主页面与浮动面板采用一致的缩略图组件

新增聚焦于展示的共享 SwiftUI 组件，由行视图传入记录 ID、内容类型、显示尺寸和 Clipboard 服务。组件通过 `.task(id:)` 异步加载，并在行复用或记录变化时取消旧任务。

- 主页面图片缩略图显示区域为 48 × 48 pt。
- 浮动面板图片缩略图显示区域为 40 × 40 pt。
- 图片使用 `scaledToFit` 保持宽高比，并使用轻量圆角与系统语义背景。
- 非图片记录继续显示现有内容类型符号，不触发缩略图读取。

加载期间以及读取、格式校验或解码失败时，组件在相同区域显示通用图片图标，避免行布局跳动。图片记录仍保留“图片”文字、来源应用、内容类型和相对时间。

### 4. 失败保持局部且不暴露隐私

缩略图失败只影响预览，不影响选择、复制、自动粘贴、收藏或删除。UI 不显示 payload 路径或底层解码错误。

日志如需记录缩略图事件，只能包含稳定事件名、错误代码和内容类型；不得包含图片数据、内容哈希、记录 ID、payload 文件名或本地路径。

## Risks And Mitigations

- 超大图片可能造成内存峰值或滚动卡顿：使用 ImageIO 源缩略图降采样、异步执行和有成本上限的内存缓存。
- 损坏或不受支持的图片格式可能无法生成缩略图：显示通用图片图标，其他操作继续使用原有路径。
- 快速滚动可能产生过期任务：组件使用记录 ID 驱动的可取消任务，只提交当前记录的结果。
- 透明或极端宽高比图片可能难以辨认：使用系统语义底色、`scaledToFit` 和固定预览区域，不裁切内容。

## Verification Strategy

- 服务测试覆盖有效图片、非图片记录、缺失 payload、损坏图片及不可用服务。
- 验证缩略图输出像素尺寸受限，且不会把原始 payload 或路径写入日志。
- 完整 Debug 构建和 Clipboard 相关 XCTest。
- 人工验证主页面与浮动面板中的横图、竖图、透明图片、损坏图片、浅色/深色模式和快速滚动。
